# 第 1 回 中間表現(FlowchartIR)

> 所要時間の目安: 2 時間 / 前提: 第 0 回

## この回のゴール

- FlowchartIR の**構成要素**(ノード・エッジ・種別・行範囲)を説明できる。
- IR を**検証**し、**Mermaid のテキスト**にできる。
- **図形の決めごと表**(種別 → 図形)と、ラベルの**エスケープ**の理由を説明できる。

## 1. 形

```typescript
// 抜粋ファイル: core/flowchart-ir/schema.ts
export type NodeKind =
  "start" | "end" | "process" | "decision" | "loop" | "ioOperation";
export interface FlowchartNode {
  id: string;
  kind: NodeKind;
  label: string;
  sourceRange: SourceRange;
export interface FlowchartEdge {
  from: string;
  to: string;
  label?: EdgeLabel;
export interface FlowchartIR {
  nodes: FlowchartNode[];
  edges: FlowchartEdge[];
  sourceFile: string;
  generatedAt: string;
```

- **ノード**: `id`(`n1`、`n2` …)・種別・ラベル(画面に出す文)・**元のコードの行範囲**(クリックで飛ぶため)。
- **エッジ**: `from` → `to`。分岐から出る線にだけ、ラベル `true` / `false`(**スキーマが許すのは `true`・`false`・空だけ**。switch の `case` の値は出さない)。
- **差分用の任意の項目**(`diff`・`previousLabel`)は、**差分を作る側だけが付ける**。抽出器は付けない。通常の IR には現れない。

## 3. Mermaid に直す

```javascript
// 実行できる
const { validateFlowchartIR } = require("../core/dist/flowchart-ir/schema");
const { emitMermaid } = require("../core/dist/render/mermaid-emitter");

const range = { startLine: 1, endLine: 1 };
const ir = {
  nodes: [
    { id: "n1", kind: "start", label: "Check()", sourceRange: range },
    { id: "n2", kind: "decision", label: "if (a < b && ok)", sourceRange: range },
    { id: "n3", kind: "process", label: 'Log("x");', sourceRange: range },
    { id: "n4", kind: "end", label: "End", sourceRange: range },
  ],
  edges: [
    { from: "n1", to: "n2" },
    { from: "n2", to: "n3", label: "true" },
    { from: "n2", to: "n4", label: "false" },
    { from: "n3", to: "n4" },
  ],

  generatedAt: "2026-01-01T00:00:00Z",
};

console.log("検証:", validateFlowchartIR(ir));
console.log(emitMermaid(ir));

const broken = { ...ir, nodes: [...ir.nodes, { ...ir.nodes[0] }], edges: [...ir.edges, { from: "n9", to: "n1" }] };

```

```text
# 出力
検証: []
flowchart TD
  n1("Check()")
  n2{"if (a #lt; b #amp;#amp; ok)"}
  n3["Log(#quot;x#quot;);"]
  n4("End")
  n1 --> n2
  n2 -->|true| n3
  n2 -->|false| n4
  n3 --> n4
[ '重複したノードID: n1', '存在しないノードIDへの参照 (from): n9' ]
```

- **図形の決めごと**: 開始・終了=角丸 `(…)`・処理=長方形 `[…]`・分岐=ひし形 `{…}`・繰り返し=六角形 `{{…}}`・入出力=平行四辺形 `[/…/]`。**3 つのホストと Webview で、同じ表**を使う。
- **エスケープ**: `<` を素通しすると、`i<n` が **HTML のタグ**と解釈されて消える。そこで `#lt;`(Mermaid のエンティティ)にする。`"` も `#quot;`。ラベルは**必ずダブルクォートで囲み**、中を直す。
- 出力は、**Mermaid Live Editor にそのまま貼れる**普通のテキスト(独自の書式は無い)。

## 確認問題

1. エッジの `label` に入れてよい値は何ですか。
2. `validateFlowchartIR` が見つけるのは、どんな問題ですか。見つけないものは何ですか。
3. ラベルに `i<n` があるとき、Mermaid ではどう書かれますか。理由も答えてください。
4. 「分岐」と「繰り返し」は、図でどう見分けますか。

## 解答

1. `"true"`・`"false"`・空(なし)だけ。
2. ノード ID の重複と、存在しないノードへの参照。到達できるかどうか・ラベルの中身は見ない。
3. `i #lt; n`。`<` がタグとして解釈されて消えるのを防ぐため。
4. 分岐はひし形 `{…}`、繰り返しは六角形 `{{…}}`。

## まとめ

- IR は、**ノード(種別・ラベル・行範囲)とエッジ(true / false)**だけの、ホストに依存しない形。
- 検証は構造だけ。図形は**1 つの決めごと表**に固定し、ラベルは**エスケープ**する。
- 次の回は、コードの**文字列とコメント**を、構文と取り違えないための下ごしらえ。
