# 第 0 回 全体の見取り図

> 所要時間の目安: 1 時間 / 前提: TypeScript か C# の基本(関数・if・for)

## この回のゴール

- この拡張が**何をして、何をしないか**を説明できる。
- **3 つの IDE**(VS Code・Visual Studio・Rider)で、**何が違い、何が共通か**を説明できる。
- 「抽出はホスト固有・IR と描画は共有」という**非対称な戦略**の理由を説明できる。

## 1. 解きたい問題

書いたコードの**分岐と繰り返し**は、読むと追いにくい。関数を、**開発中のエディタのまま**、フローチャートにして見たい。

![構成図](../diagrams/architecture.svg)

- カーソルのある関数 → 図(開始・処理・分岐・繰り返し・終了)。
- ノードを押すと、**その行へ飛ぶ**。
- Git の HEAD と比べて、**変わった所だけ**を色分けする(差分)。
- 全体 › ファイル › 関数 と、**階層を掘り下げる**(CodeBoarding の出力を読む)。

**やらないこと**: コードの**実行**(実行順に線を引く「再生」は、図の上の演出)・**意味の解析**(型・呼び出し先の解決)・コードの書き換え。

## 2. 3 つの IDE で、何が違うか

| ホスト | 言語 | コードの読み方 | 状態 |
|---|---|---|---|
| VS Code | TypeScript | **関数の特定**は DocumentSymbol。中身は括弧の走査で読む。シンボルが取れない言語は tree-sitter、それも使えなければ括弧の走査(**3 段のフォールバック**) | 実機で検証済み |
| Visual Studio | C# | Roslyn の `ControlFlowGraph` → SyntaxWalker | コンパイル確認のみ(実機の VS は未確認) |
| Rider | Kotlin | Java の PSI(C# は未対応) | ビルド未確認 |

**読む側は、IDE ごとにまったく別物**です(各 IDE が持つ解析の仕組みが違うため)。それでも、**出力はどれも同じ形**(FlowchartIR)にそろえます。

## 3. 非対称な戦略

```
  [ホスト固有]            [共有]                    [共有]
  コードを読む   →   FlowchartIR   →   Webview バンドル(描画・操作)
  (3 通り)           (1 つの形)          (3 ホストで同じファイル)
```

- **抽出**(コード → IR)は、ホストごとに実装する。**IDE の API に頼る方が、正確で速い**から。
- **IR と描画**は、1 つだけ持つ。**図の見た目・操作・差分・書き出しを、3 回作らない**ため。
- IR の型は、**ホスト固有の型を一切参照しない**(`vscode.*`・Roslyn・`PsiElement` を、IR の層に漏らさない)。

> この約束が破られると、「VS Code では動くが、Rider では動かない」図が出てくる。IR の層を**純粋に保つ**ことが、保守の核心。

## 4. この講義の道のり

IR(第 1 回)→ ソースの下ごしらえ(第 2 回)→ 制御フローの組み立て(第 3 回)→ 差分(第 4 回)→ 描画とビュー(第 5 回)→ 全体の階層(第 6 回)→ テスト(第 7 回)。

## 確認問題

1. この拡張が「やらないこと」を 2 つ挙げてください。
2. 3 つの IDE で**共通**なものと、**ホスト固有**なものは、それぞれ何ですか。
3. IR の型が、ホスト固有の型を参照してはいけない理由は何ですか。
4. Rider 版で、C# の図が出ないのはなぜですか(この資料の範囲で)。

## 解答

1. コードの実行・意味の解析(型や呼び出し先の解決)・コードの書き換え。
2. 共通: FlowchartIR・Webview バンドル(描画・操作・差分・書き出し)。ホスト固有: コードの読み方(抽出)。
3. 参照すると、その IDE でしか動かなくなり、3 ホストで IR と描画を**共有できなくなる**から。
4. Rider の C# は、汎用の PSI ではなく ReSharper のバックエンド経由のモデルで、Java 向けの API では扱えない(未対応。`rider-plugin/RIDER_NOTES.md`)。

## まとめ

- 目的は、開発中のエディタ上で、関数の制御フローを図にすること。
- **読む側(抽出)はホスト固有、IR と描画は共有**。IR の層を、ホスト固有の型で汚さない。
- 検証が済んでいるのは VS Code だけ(Visual Studio はコンパイルまで、Rider は未確認)。次の回は、その共通の形(IR)。
